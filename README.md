# ScoreLyric 谱词库

ScoreLyric 是一个面向音乐学习者、教师与歌词整理者的歌谱识别和双语歌词收录平台。用户可上传图片或 PDF 歌谱，提取歌词与段落反复关系，经校对后生成中文、英文或中英双语文本，并在精简段落和完整演唱顺序之间切换。新识别的歌词完成查重与审核后进入首页最近收录库，可按歌名、歌手、专辑和歌词片段搜索。

线上演示：https://scorelyric.nmopud.chatgpt.site

## 当前状态

当前处于 `M0 · 产品原型完成`：前端界面、示例数据、核心交互和响应式布局已经实现，真实数据库、文件上传、OCR、翻译及校对工作流尚未接入。

已实现：

- 沉浸式首页最近收录库
- 按歌名、歌手、专辑和歌词片段即时搜索
- 六首示例歌词、真实专辑封面及独立详情页
- 专辑切换、歌词详情跳转与响应式移动布局
- 中英双语、段落标签和反复次数展示
- 歌谱上传工作台及语言、段落、公开收录选项
- 中文、英文、中英双语与精简、完整段落的产品入口
- 移除前台 AI 服务中心，识别服务仅保留为服务端配置能力

## 产品原则

1. 一台 CPU 云服务器即可启动，不把 GPU 作为上线前提。
2. OCR 与翻译采用可替换适配器，业务数据不绑定单一服务商。
3. 本地 OCR 为默认主通道；低置信度或结构解析失败时才允许受控兜底。
4. API Key 只保存在服务器环境变量或密钥系统中，前端和日志不返回完整密钥。
5. 中文、英文、双语以及精简、完整版本共用识别缓存，避免重复计费。
6. 原始歌谱默认私有；公开收录必须经过校对、查重和版权治理。
7. 首页首先是可搜索的歌词收录库，识别工具服务于内容沉淀，不喧宾夺主。

## 生产架构规划

- Web：Next.js、React、TypeScript
- API：FastAPI、Python
- 数据：PostgreSQL，使用全文索引与 `pg_trgm`
- 队列：Redis + RQ，CPU OCR Worker 初始并发为 1
- OCR：OpenCV + PaddleOCR CPU
- 翻译与复杂识别：通过服务端适配器按需接入正式 API
- 文件：本机磁盘起步，预留 S3 兼容对象存储接口
- 部署：单台 CPU 云服务器、Docker Compose、Caddy 或 Nginx
- 监控：结构化日志、任务失败告警、服务额度与延迟统计

## 个人 Codex 开发计划

开发方式遵循“单人决策、Codex 执行、每个里程碑可运行验收”。每次只保留一个进行中任务，不跨里程碑堆叠未验证功能。

### M0：产品原型与视觉方向（已完成）

目标：验证首页收录库、歌词详情、歌谱识别入口和中英文输出选择是否成立。

交付：

- 首页、详情页、识别工作台
- 六首 DEMO 数据与专辑封面
- 桌面端和移动端响应式布局
- 搜索、专辑切换与详情跳转
- 自动构建、渲染测试和设计 QA

验收标准：`npm run build`、`npm test`、`npm run lint` 通过，核心页面可在浏览器完成主流程。

### M1：数据库与歌词收录闭环

目标：把 DEMO 数据替换为可新增、查询和维护的真实数据。

任务：

- 建立歌曲、歌手、专辑、封面、歌词版本、段落和识别任务数据模型
- 接入 PostgreSQL 迁移与种子数据
- 首页、搜索和详情页改为服务端数据
- 新识别歌词默认进入“待校对”，通过审核后进入最近收录
- 增加歌手、专辑、年份、语言和歌词片段联合搜索

验收标准：可新增一首歌曲并在首页检索；重复歌曲不会产生第二条公开记录。

### M2：上传、OCR 与段落结构识别

目标：在 CPU 服务器上完成从歌谱文件到可校对歌词草稿的异步流程。

任务：

- 校验 JPG、PNG、WebP、PDF 的类型、大小和页数
- 清理图片方向与隐私元数据，生成文件哈希用于查重
- 接入 PaddleOCR CPU 适配器
- 设计统一 OCR JSON 契约，保留页码、文本块、置信度和坐标
- 识别主歌、副歌、反复记号与演唱顺序
- 建立排队、处理中、待校对、失败、完成任务状态

验收标准：首批 30–50 份测试歌谱形成评估集，文字召回率、段落准确率和平均处理时间均有记录。

### M3：校对、翻译与多版本输出

目标：让用户能够修正识别结果并生成稳定的中文、英文和双语歌词。

任务：

- 可视化校对 OCR 文本与段落结构
- 生成中文、英文和中英双语版本
- 支持精简段落与完整演唱顺序
- 对相同内容使用缓存，避免界面切换重复调用翻译服务
- 保存版本历史、修改人、时间和回滚点

验收标准：用户可从上传开始完成识别、校对、翻译、预览和申请收录全过程。

### M4：歌词库管理与版权治理

目标：让首页从演示库升级为可长期维护的公开歌词档案。

任务：

- 歌手、专辑、歌曲和歌词版本管理
- 私有草稿、待审核、公开和下架状态
- 原图访问权限、删除申请与版权投诉流程
- 搜索排序、热门查询、最近收录和相关歌曲
- 管理员审核日志与敏感操作审计

验收标准：所有公开内容有来源、审核状态和可追溯修改记录，私有原图不可被未授权访问。

### M5：单机上线与运营验证

目标：以最低成本在一台 CPU 云服务器上稳定运行并验证真实使用需求。

任务：

- Docker Compose 编排 Web、API、PostgreSQL、Redis 和 OCR Worker
- 配置 HTTPS、备份、日志轮转、限流和异常告警
- 建立 OCR/翻译额度上限、超时和失败降级
- 记录识别成功率、校对耗时、公开收录率和搜索使用率
- 根据真实使用数据决定是否增加 GPU、对象存储或更多识别服务

验收标准：连续运行 30 天，无数据丢失；关键任务失败可定位、可重试、可告警。

## 本地运行

需要 Node.js 22.13 或更高版本。

```bash
npm ci
npm run dev
```

生产构建与测试：

```bash
npm run build
npm test
npm run lint
```

## 安全边界

- `.env`、真实 API Key 和部署凭据不提交到仓库
- 不抓取或模拟免费在线 Chat 网页，只使用供应商正式 API
- API 调用必须设置超时、有限重试、日/月额度和脱敏日志
- 用户私有原图、草稿和识别结果必须执行服务端权限校验
- 删除数据、发布生产和修改访问权限必须经过明确授权

## 开发节奏

项目由个人主导，Codex 协助编码、测试、文档与部署。每个任务必须以代码提交、自动测试、浏览器验收或可复核文档作为完成证据。
